# 大QMT 做不到或做法不同的内容

依据：khQuant V3.4.1.11 源码与官网教程（3.1 框架介绍、3.2 策略工具箱、1.7 回测配置、1.8 触发方式、1.12 设置）；迅投知识库内置 Python 手册（dict.thinktrader.net，线上文件时间 2026-07-27）。手册没写明的行为一律按「需实测」处理，不要替 QMT 下结论。

每次迁移前，逐条对照用户策略实际用到的功能，在迁移报告里列出命中的条目。

## 目录

- 一、大QMT 做不到（没有对应能力）
- 二、做法不同（兼容层或改写能模拟，结果可能有小差异）
- 三、手册没写明，要在 QMT 里实测
- 四、迁移后能多出来的能力（给用户的参考）

## 一、大QMT 做不到（没有对应能力）

| # | khQuant 功能 | 大QMT 的情况 | 迁移时怎么处理 |
|---|---|---|---|
| A1 | 用 khQuant 自己下载的行情回测（BaoStock、Tushare、tx、同花顺等数据源导入的 DuckDB 库） | QMT 回测只读它自己「数据管理」下载的行情，不能指定外部数据库当行情源 | 在 QMT 里补下载同周期行情。两边行情源和复权算法不同，回测结果会有差异，必须先告诉用户 |
| A2 | DuckDB 里的自定义指标列：`khDuckWrite` 写库、`khAddExtraFields` 注册、`khIndex` 读取；策略里用 `khDuckDB` 读库 | QMT 读不到 khQuant 的 DuckDB | 在策略里现算指标；或在 khQuant 这边把指标导出成 CSV，在 `kh_init` 里用 `open()` 读进全局字典（路径写死，注意编码）。迅投投研版另有「扩展数据」接口，券商版不一定有，不作为默认方案 |
| A3 | `khDuckDB` 日线里的 BaoStock 字段：`peTTM`、`pbMRQ`、`psTTM`、`pcfNcfTTM`、`turn`、`pctChg`、`isST` | QMT 没有同名字段 | 换成 QMT 的 `get_financial_data`、`get_turnover_rate`、`get_st_status` 等，先补下载财务数据。口径、单位、历史可得性都不同，换算后要抽样核对 |
| A4 | 命令行回测 `kh run`、网页工作台 `kh web`、批量参数研究、让 AI 自动跑回测循环 | QMT 回测只能在策略编辑器里点「回测」，没有命令行入口 | 参数遍历用策略编辑器「参数设置」的最小/最大/步长；大批量研究留在 khQuant 做，选定参数后再迁移 |
| A5 | 回测结果文件：`summary.csv`、`trades.csv`、`daily_stats.csv`、`benchmark.csv`、HTML 报告 | 结果在 QMT 界面查看，右键复制或导出 | 对账时让用户导出「操作明细」，和 khQuant 的 `trades.csv` 逐笔比 |
| A6 | 回归金标准、性能预设（全量 / 分段加载）、`kh tool parquet-cache` | 无 | 不迁移 |
| A7 | macOS、Linux、Web 运行 | QMT 只有 Windows 客户端 | 告知用户 |
| A8 | Python 3.11 环境、在软件里自装第三方库 | 内置 Python 固定 3.6；第三方库要在券商白名单里，装到 `{安装目录}\bin.x64\Lib\site-packages` | 用到的库先问券商；`khQuantImport`、`MyTT`、`khChanLunTools` 不能直接 import，把用到的函数复制进策略文件。语法和标准库要降到 3.6（见 SKILL.md 的 3.6 清单） |
| A9 | 策略里自己开线程、进程池 | 手册写明内置 Python 不能多线程、多进程，所有策略共用一个线程，阻塞会拖住同客户端其他策略 | 改成单线程顺序计算；重计算放到盘后的 khQuant 或独立脚本里提前算好 |
| A10 | V3 内置 VS Code 断点调试 | QMT 只能看日志输出 | 用 `print` 打关键变量 |
| A11 | 自定义定时触发里带秒的时间点（如 09:30:15，khQuant 取该时刻前 5 秒内最新一笔 tick） | 回测按主图 K 线驱动；`run_time` 手册写明回测无效 | 整分钟时间点：主图改 1 分钟，在策略里按时间过滤（兼容层模式下在 `khHandlebar` 开头判断 `khGet(data,'time')`）。带秒的时间点在 QMT 回测里没有等价做法 |
| A12 | `is_trade_time()`、`is_trade_day()`、`get_trade_days_count()`、`get_trade_days_set()`（依赖 khQuant 本地交易日历） | 兼容层没有提供 | 回测里按时段过滤用 `khGet(data,'time')`；要交易日列表用 `C.get_trading_dates`（只能在 `after_init` 或 `handlebar` 里调用） |
| A13 | `khKline` 任意周期拼接（含当前未收线的半根、多日周期按年初对齐） | QMT 有合成周期（3m、15m、30m、1h、2d、1w 等，由基础周期合成），对齐和含不含当前根的规则不同 | 用 `get_market_data_ex` 取合成周期，并自己处理最后一根是否收线；结果要和 khQuant 抽样对比 |
| A14 | 回测指标口径（年化、最大回撤、夏普、Alpha/Beta） | 由 QMT 自己计算，算法不同 | 不比指标数值，比逐笔成交和每日资产 |

## 二、做法不同（兼容层或改写能模拟，结果可能有小差异）

兼容层 `assets/kh_compat_qmt.py` 已经实现下表「兼容层」一列写「已模拟」的项目；走原生改写路线时要自己按 `function-mapping.md` 写。

| # | khQuant 规则 | 大QMT 回测规则 | 兼容层 | 残余差异 |
|---|---|---|---|---|
| B1 | 回调返回信号列表，框架统一撮合 | 在 `handlebar` 里直接调 `passorder`，没有返回值 | 已模拟：照 khQuant 规则算出成交价，用指定价（prType 11）下单 | 无 |
| B2 | 市价单：按信号价成交；买价高于当根最高、卖价低于当根最低时改按开盘价（判断前先把高低点取整到分）；加滑点后的成交价取整到分，可以落在当根高低点之外 | 指定价在当根高低点之间按指定价成交，超出按收盘价成交 | 已模拟：越界判断和 khQuant 一样先取整；委托价超出区间时按区间端点下单并提示一次。默认 `slippage_mode='commission'`，委托价不含滑点，很少越界 | `price` 模式下，按收盘价或开盘价成交的策略经常碰到越界（实测一个单边滑点 0.5% 的策略，28 笔里 17 笔），滑点被吞掉一部分，期末资产偏高可达几个百分点；`commission` 模式只在复权价有三位小数时有不超过 0.01 元的差。资金不同会让后续股数差一两手 |
| B3 | 限价单、止损单、止损限价单；`day` / `gtd` / `max_pending_bars` 有效期；挂单跨 K 线继续撮合；`khGetPendingOrders`、`khCancelOrder` 等 | 回测里没有挂单队列和止损触发，委托当根就按 B2 的规则成交 | 已模拟：策略内部维护挂单簿，每根 K 线按 khQuant 规则判断是否成交，成交时才向 QMT 下单 | 与 B2 相同 |
| B4 | 盘前回调 `khPreMarket`（默认 08:30，看上一交易日数据，信号转当日限价单）、盘后回调 `khPostMarket`（默认 15:30，信号转下一交易日限价单） | 没有对应回调 | 已模拟，只支持日线周期 | 分钟周期不支持；回测最后一天的盘后回调不执行（khQuant 执行但信号不会成交） |
| B5 | 日内多次触发 `khRequestNextDailyTrigger`（同一根日线再调一次，账户已反映上一轮成交） | 没有让同一根 K 线再触发一次的接口 | 已模拟：同一次 `handlebar` 里循环调用，账户用本地副本按 khQuant 费用推算 | QMT 回测里卖出后资金是否当根可用，见 C3 |
| B6 | 涨跌停：不复权时，一字涨停不能买、一字跌停不能卖，收盘价在涨停价不能买、在跌停价不能卖，限价单委托价越出涨跌停直接拒单；复权回测不校验 | 手册没写回测会做涨跌停校验；`get_instrument_detail` 的涨跌停价是当天的，不能用于历史 | 已模拟：按 khQuant 口径用 `preClose` 计算，只在不复权时生效 | ST 股按 10% 处理（khQuant 行情里通常也拿不到股票名） |
| B7 | T+1：当天买入的部分不能卖；股票池全部是 T+0 ETF 时自动 T+0（清单在 khQuant 的 `data/T0型ETF.csv`，同目录还有 `T0股票型ETF列表.csv`、`T0QDII基金列表.csv` 等） | 手册只写「委托数量大于可用数量时按可用数量撮合」 | 已模拟：自己记录当天买入量；T+0 要在 `t0_codes` 里列出代码 | QMT 自己的可用数量规则见 C4；自检会打印同一天买入后 QMT 查到的可卖数量 |
| B8 | `generate_signal` / `calculate_max_buy_volume` 按 khQuant 费用和滑点算股数 | 无同类函数 | 已模拟，同名函数；下单前再按 QMT 收费口径（回测参数里的佣金率）核一遍资金，不够就减一手 | 满仓买入时偶尔比 khQuant 少一手，日志会提示 |
| B9 | `khHistory` 不含 `current_time` 那一根；`khMA` 截至前一根；`fq` 默认跟随回测复权 | `get_market_data_ex(end_time=当前K线)` 含当前这一根；`dividend_type='follow'` 跟随主图 | 已模拟：多取一根再去掉当前根 | 行情源不同导致的数值差异（A1） |
| B10 | 日线 `data` 里当天 K 线是完整的；日线时间显示 09:30:00 | 日线 `handlebar` 时当根 K 线也是完整的 | 已模拟：日线 `time` 统一给 09:30:00 | 无 |
| B11 | `logging.info/warning/error`，`[TRADE]` 高亮 | 日志面板显示 `print` | 已模拟：`logging` 转成 `print` | 没有高亮 |
| B12 | 股票池来自 `.kh` 的 `stock_list`、板块勾选或 CSV，作为 `init` 的第一个参数 | 主图品种 + 策略里自己写股票池；`get_stock_list_in_sector` 用 QMT 的板块名 | 已模拟：`KH_CONFIG['stock_list']` | 板块成分要写死成代码列表，避免两边板块定义不同 |
| B13 | 策略状态存在模块全局变量里 | `ContextInfo` 上的属性每根 K 线会回滚；手册禁止往上挂自定义属性 | 兼容层状态存在模块全局 `_S`；策略原来的全局变量照常可用 | 无 |
| B14 | 价格精度：股票 2 位、ETF/LOF 3 位，`round_price`、`get_price_decimals` | 委托价按交易所精度 | 已模拟，同名函数 | 无 |
| B15 | 交易费用：佣金（含最低）、卖出印花税（ETF/LOF 免）、过户费按「成交日期 × 市场」分段自动计算、流量费每笔固定、印花税可按 2023-08-28 自动切换 | 回测参数只有手续费类型、买入/卖出印花税、最低佣金、买入佣金、平昨/平今佣金，费率框单位是 %（实测）；没有过户费、流量费项，印花税是一个固定值 | 兼容层只用 khQuant 口径估算股数；QMT 实际扣费按界面填写。成品 `[设置]` 行打印的是换算好的百分数，实测买入、卖出扣费和它分毫不差 | 把过户费近似折进佣金率（2022-04-29 之后加 0.00001）；跨 2023-08-28 的区间可分两段回测或接受误差 |
| B16 | 滑点两种算法：按跳数（默认每跳 0.01 元）或按比例（买卖各一半），加滑点后取整到分；限价单加滑点不越过限价 | 回测参数有「滑点类型」（默认按成交额比例）和「滑点值」（单位 %），滑点怎么作用到成交价手册未写 | 两种模式，QMT 界面滑点值都填 0：`commission`（默认）把单边滑点比例加进佣金率，`init` 打印该填的值；`price` 把滑点加进委托价。离线自检两种都跑，推荐期末资产更接近的那种 | 滑点每股不到一分钱时，khQuant 取整后常常没有滑点，`commission` 模式会多收，这时选 `price`；按跳数的滑点折成比例要按价格换算，股票池价格差别大时也选 `price` |
| B17 | 成交量限制：单笔不超过当根成交量 × 参与率，剩余继续挂单；可关闭「允许部分成交」 | 回测参数有「最大成交比例」，剩余数量怎么处理手册未写 | 兼容层没有模拟成交量限制 | 开了成交量限制的策略要在 QMT 里实测（C5） |

## 三、手册没写明，要在 QMT 里实测

迁移报告里把下面命中的条目列为「上线前实测项」，给出最小测试方法。

| # | 问题 | 最小测试方法 |
|---|---|---|
| C1 | 回测账号：官方两个示例写法不一致（一个查询用 `'test'`、下单用 `'testS'`，另一个查询和下单用同一个字符串） | **已实测（2026-11-01，券商版大QMT）**：任意字符串（如 `kh_backtest`）都能查到初始资金并成交，查询和下单用同一个字符串即可。兼容层就是这样写的；`selfcheck` 仍会打印查到的资金，换券商时看一眼 |
| C2 | 回测里的「滑点」值是跳数、比例还是金额 | 兼容层不依赖它（界面滑点填 0）。想弄清楚时，单独写一个按指定价买 100 股的测试策略，界面滑点填一个值，看操作明细里的成交价 |
| C3 | 回测里同一根 K 线先卖后买，卖出所得资金能否立即用于买入；`get_trade_detail_data` 是否当根就反映成交 | 写一根 K 线内先卖后买的测试，打印买入前后查到的资金和持仓 |
| C4 | 回测是否按 T+1 计算可卖数量，T+0 ETF 是否允许当天卖出 | 已实测一半：股票日线买入后，下一根 K 线可卖数量等于买入量。T+0 ETF 当天能否卖出还没测：用分钟线买入当天立即卖出，看 `[自检]` 打印的可卖数量和操作明细 |
| C5 | 「最大成交比例」超出部分是丢弃还是挂到后面成交 | 小盘股大资金买入，看操作明细里的成交量 |
| C6 | 回测是否做涨跌停校验 | 关掉兼容层涨跌停（`check_price_limit=False`），在一字涨停日买入，看是否成交 |
| C7 | ETF/LOF 卖出是否自动免印花税 | 卖出一笔 ETF，看操作明细里的税费 |
| C8 | `get_market_data_ex` 返回的 DataFrame 行索引格式（日期字符串还是时间戳） | **已实测**：日线是字符串 `'20230103'`。兼容层两种格式都兼容；分钟线格式没测，`[自检]` 会打印一次 |
| C9 | K 线 `volume` 单位（khQuant DuckDB 统一为手） | 打印同一天同一只股票的成交量，和 khQuant `kh data info` 对比 |
| C10 | QMT 前复权的算法（等差还是等比）和 khQuant 数据源是否一致 | **已实测，不一致**：2023–2024 整段，QMT 主图选「前复权」取到的价格比 khQuant DuckDB 前复权价低一个固定金额（000001.SZ 约 0.25 元，600000.SH 约 0.42 元），比值随价格漂移。均线交叉、跌破均线这类比较不受固定差额影响；按资金算出的股数和百分比收益会变。一个双均线策略实测：63 笔共同成交股数全部不同（最多差 2500 股），期末资产差 −0.66%。要对得更近，可以试主图和 `dividend_type` 都改成等比前复权（`front_ratio`）再比，这一步还没测 |
| C11 | QMT 内置 pandas、numpy 版本对策略里用到的 API 是否支持 | 在 `kh_init` 里打印 `pd.__version__`、`np.__version__` |
| C12 | `schedule_run` 在回测里是否生效（`run_time` 手册已写明无效） | 不依赖它；需要定时就用主图周期加时间过滤 |
| C13 | 分笔（tick）主图回测的撮合规则 | khQuant tick 策略迁移前先单独实测，不承诺和 khQuant tick 回测一致 |

## 四、迁移后能多出来的能力（给用户的参考）

- 在「模型交易」里接模拟柜台或实盘柜台下单（需要单独改写，见 `live-trading.md`）。
- 两融、期货、期权、可转债转股、ETF 申赎、新股申购等交易类型。
- 算法交易 `algo_passorder`、智能算法 `smart_algo_passorder`（需券商开权限）。
- 财务数据、龙虎榜、北向资金、ETF 申赎清单等行情接口（多数需要先下载数据）。
- Level2 行情（需要权限）。
