# 迁移后转到 QMT 模拟盘或实盘

兼容层只为回测对账设计：它在策略内部模拟 khQuant 的挂单和撮合，再用指定价向 QMT 下单。实盘里行情是逐笔推送的，委托是异步的，这套模拟会出错。用户要在 QMT 里跑模拟盘或实盘时，按下面的要求另写一份实盘版，并提醒用户先在模拟柜台跑通。

本 skill 只负责写代码和说明，不替用户在 QMT 里启动实盘、不下真实委托。

## 1. 运行入口

- 回测在策略编辑器里点「回测」；模拟盘和实盘要在「模型交易」里新建策略交易，选择账号、品种、周期和运行模式。
- 运行模式「模拟」只显示信号，不发委托；「实盘」才真正报单。运行模式和账号是模拟柜台还是真实柜台无关。
- 在编辑器里点「运行」不会产生委托。
- 账号从模型交易界面传进来：策略里用全局变量 `account`、`accountType`（官方实盘示例写法）。两融账号买卖代码用 33/34（担保品买卖），普通账号用 23/24。

## 2. handlebar 在实盘里怎么触发

- 先对历史 K 线逐根调用一遍，然后盘中主图每来一笔分笔（股票约 3 秒一笔）调用一次。
- 用 `C.is_last_bar()` 跳过历史 K 线，否则一启动就会对历史信号下单。
- 主图是股票时分笔约 3 秒一次；需要更快或更准时的触发，用 `subscribe_quote` 回调或 `run_time` / `schedule_run` 定时器。
- 非交易时段行情服务重连也会触发 `handlebar`，在开头按时间过滤（例如早于 09:15 直接返回）。

## 3. quickTrade 参数

| 值 | 行为 | 用法 |
|---|---|---|
| 0（默认） | 信号暂存到这根 K 线结束，下一根第一个分笔才报出；日线及以上周期全天不委托 | 模拟逐 K 线效果 |
| 1 | 只在最新一根非历史 K 线上报出，可能信号闪烁 | 盘中立即下单的常用选择 |
| 2 | 不判断 K 线状态立即报出，历史 K 线也会报 | 定时器、行情回调、`after_init` 里下单必须用 2，否则漏单；`handlebar` 里用 2 时自己过滤历史 K 线 |

完整写法：`passorder(opType, orderType, accountid, orderCode, prType, price, volume, strategyName, quickTrade, userOrderId, C)`，`userOrderId` 是投资备注，填它时 `strategyName` 和 `quickTrade` 也要填。

## 4. 防止超单

- 交易接口是异步的；`get_trade_detail_data` 和交易回调读的是客户端本地缓存，有主推时约 50 毫秒刷新，无主推时 1–6 秒。刚下单马上查，可能查不到委托，卖出后资金也不会马上增加。
- 按官方做法：用投资备注做键，维护一个全局委托状态表；下单时先记为「待报」，某个品种还有没查到的委托时暂停它的后续报单。官方完整示例「调整至目标持仓」用 `waiting_dict` 做了这件事，可以照抄结构。
- `cancel` 返回 True 只表示撤单请求已经发出，要看委托状态确认。委托状态码：49 待报、50 已报、51 已报待撤、52 部成待撤、53 部撤、54 已撤、55 部成、56 已成、57 废单。
- 交易回调（`order_callback`、`deal_callback` 等）要先在 `init` 里调用 `C.set_account(account)`，只在实盘模式生效。

## 5. 交易所规则（回测里没有，实盘会废单）

- 股票报价超出价格笼子（2%）会废单。
- 卖出数量超过可用数量会废单。
- 单笔数量：主板 100 股起、按 100 股递增、单笔最多 100 万股；创业板限价单最多 30 万股；科创板 200 股起、按 1 股递增，限价单最多 10 万股。
- 市价类报价（prType 42–48）在集合竞价阶段、部分品种上有限制，按交易所规则选。

## 6. khQuant 功能在实盘里的替代

| khQuant | 实盘写法 |
|---|---|
| 限价单、挂单队列 | 直接报限价委托（prType 11 指定价），用 `get_trade_detail_data(..., 'order')` 查状态，`cancel` 撤单 |
| 止损单 | 盘中用行情回调或定时器监控价格，触发后报单 |
| 盘前回调 | `after_init` 或 `schedule_run` 定在开盘前的时间（`quickTrade=2`） |
| 盘后回调 | 收盘后的定时任务里计算，结果存文件，第二天开盘前读入 |
| 日内多次触发 | 先报卖单，确认成交后再报买单 |
| `generate_signal` 的股数计算 | 实时查可用资金和可卖数量（`m_nCanUseVolume`）再算，注意本地缓存延迟 |

## 7. 上线前检查

1. 先用模拟柜台账号在「模型交易 → 实盘模式」跑至少几个交易日，核对委托、成交和持仓。
2. 确认股票池里每只都下载了所需历史数据，开盘前数据已更新。
3. 确认没有阻塞写法（长循环、`time.sleep`、网络请求），它会拖住同客户端所有策略。
4. 留意客户端定时重启（券商客户端可能每天自动重启），重启后策略要能从持仓和委托状态恢复，不能重复下单。
