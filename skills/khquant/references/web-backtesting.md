# 网页回测工作台

## 定位与边界

- 网页端是既有 `kh` CLI 和回测核心的操作界面，不是第二套回测系统；相同 `.kh`、策略、数据和设置应得到与 CLI/桌面端一致的结果。
- 回测数据源固定为桌面端设置的 DuckDB，不支持在网页端切换到 miniQMT 直接回测。
- 当前版本聚焦回测；数据管理暂不提供。设置页以只读方式展示桌面端全局配置，避免两端配置分叉。
- 默认地址是 `http://127.0.0.1:8766/`，仅本机可访问。端口 `8765` 属于桌面内置编辑器通信，不要混用。
- V3.4.0 的 Windows、macOS 桌面版及 Linux wheel/Docker 使用同一套 Web 前后端和回测协议；Linux 不包含 PyQt 桌面 GUI，但正式支持 `kh web`。

## 启动方式

```bash
kh web
kh web "D:\strategies\example.kh"
kh web --no-open
kh web example.kh --host 0.0.0.0 --port 18771
```

- `kh web`：打开网页工作台并恢复最近项目。
- `kh web <配置.kh>`：先导入配置及策略依赖，再打开对应项目。
- `--no-open`：只启动服务，不主动打开浏览器。
- 桌面端工具栏的网页图标调用相同入口；已加载 `.kh` 时自动带入，未加载时进入工作台首页。
- 桌面端以独立进程启动网页服务，关闭桌面主界面不会结束网页服务；再次点击会复用已启动的服务。
- 源码模式和安装包模式都必须能启动网页端。排错时先确认实际启动的是哪套 Python/安装目录。

## 局域网、临时公网与服务器部署

- 局域网访问可使用 `kh web --host 0.0.0.0 --port 8766 --no-open`。非回环监听会生成随机访问密钥，必须使用终端给出的带密钥网址访问。
- “一键临时访问”通过 Cloudflare Quick Tunnel 生成临时 HTTPS 地址，不要求公网 IP 或路由器端口映射；停止后公网地址和访问密钥随即失效。桌面安装包按实际内置能力使用，源码/wheel 不捆绑第三方 `cloudflared`，需通过 PATH 或 `KHQUANT_CLOUDFLARED_PATH` 提供。
- 临时隧穿只适合临时控制，不保证固定域名或长期在线。服务器长期部署建议让 Web 只监听 `127.0.0.1`，再用 Nginx/Caddy 提供 HTTPS、自有域名和额外认证。
- 不要直接把无访问密钥的 `0.0.0.0:8766` 暴露到公网，也不要把临时访问网址或访问密钥写入公开教程、日志或仓库。

## 导入策略项目

本机使用时优先只选一个 `.kh`：

1. 在空工作台点击“导入第一个项目”，或顶部点击“导入”。
2. 选择“本机文件”，打开系统文件选择框选中 `.kh`；也可手动输入完整路径。
3. 系统读取 `.kh` 的 `strategy_file`，自动复制入口 `.py`、递归引用的本地 Python 依赖和配置引用的股票池 CSV。
4. 导入内容进入共享策略项目目录，原始文件不修改。

远程浏览器无法弹出服务器本机的文件选择框。此时应上传完整项目文件/目录，或填写服务器能访问的 `.kh` 路径。

## 页面结构

左侧导航包含：

- **回测工作台**：编辑参数、运行回测、查看实时状态和最近结果。
- **策略项目**：切换已导入项目。
- **历史结果**：查看网页端、桌面端和 CLI 的统一结果列表，打开或清理报告。
- **设置与状态**：查看软件版本、DuckDB 路径、性能模式、内存档位、历史预热天数和并行读取线程等桌面端设置。

工作台采用左右两栏：左侧是回测配置，右侧是运行控制、实时日志和结果摘要。日志内容再长也不能撑宽右栏。

## 配置与保存

网页控件直接映射 `.kh` 配置和 CLI 参数，不做另一套隐式转换：

- **基础设置**：开始/结束日期、初始资金、基准合约。
- **触发器**：Tick、1 分钟、5 分钟、每日、自定义时间；自定义时间支持按交易时段批量生成。
- **交易成本**：佣金、最低佣金、印花税、流量费、比例/档位滑点。
- **盘前盘后回调**：是否启用及回调时间。
- **行情数据**：K 线周期、复权方式、最小交易量、加载字段。
- **股票池**：手动输入、常用股票池追加、CSV/TXT 导入。
- **策略源码**：只读预览，网页端不直接修改策略代码。

修改参数会自动保存为项目草稿；“保存版本”用于建立一个有名称的正式配置快照。

运行前必须检查数据周期和触发方式。例如日线数据配 Tick 触发会产生不匹配警告，严重时会出现“没有找到任何有效的时间点”。不要通过忽略警告来掩盖配置问题。

## 运行回测

1. 确认日期、周期、触发器和股票池。
2. 点击顶部或右侧“运行回测”。
3. 网页先调用 CLI 预检；阻断错误必须修复，警告需要明确确认后才能继续。
4. 右侧展示运行标识、进程、启动时间、阶段和进度。
5. 初始化尚未产生百分比时显示动态“启动中”，避免把 DuckDB/框架加载误判为卡死。
6. 若网页回测读取某只股票时恰逢另一进程持续写入，底层先自动重试；仍失败时该项会被跳过，并在“本次回测结果”、HTML 报告及结果目录 `duckdb_lock_skips.csv` 中明确告警，不能当作普通无数据忽略。
7. 点击“停止回测”会沿用 CLI 控制文件和进程树停止逻辑。

网页服务状态只负责展示和控制；真正的计算、事件、报告仍由 CLI 产生。

## 实时日志

- 桌面宽屏日志框默认高约 `190px`，窄屏自动缩小。
- 页面保留并展示最近 120 行，新增日志后自动滚到最末行。
- 任务结束时会再次读取最终日志，避免极短任务在第一次轮询前结束而漏掉末尾输出。
- 页面重开后会恢复最近任务的日志。
- 日志会强制换行，不允许长路径或长消息改变右栏宽度。

排错时优先看最后几行，但同时结合运行状态和事件文件；错误日志不应仅凭界面颜色判断。

## 回测结果

- 完成后右栏以醒目外框显示“本次回测结果”；必须用 `run_id` 精确匹配当前任务，不能把旧结果误标为本次结果。
- 摘要包括总收益、年化收益、最大回撤和期末资产。
- 点击结果卡打开完整 HTML 回测报告；历史结果页也能打开同一报告。
- 当前结果与较早结果分层显示，较早结果只作为次要入口。
- HTML 报告由 CLI 结果目录生成，报告目录仍应包含 `summary.csv`、配置、交易记录及 `report.html` 等标准文件。

## 常见问题

### 页面长时间停在 0%

先判断是正常初始化还是状态同步异常：

1. 查看右侧阶段和实时日志。
2. 检查当前 CLI PID 是否存在。
3. 检查 `~/.khquant/web/current_run.json`、对应 `runs/<run_id>/events.jsonl` 和 `stderr.log`。
4. 如果事件已出现 `completed` 且结果目录完整，但页面仍显示运行中，属于状态落盘/服务状态问题，不要重跑策略冒充修复。

Windows 杀毒、索引或文件监控可能短暂占用 `current_run.json`。当前实现会对原子替换退避重试，单次写入失败也不会结束监控线程；旧进程遗留状态可通过重启网页服务恢复收口。

### 日志显示 0 行

- 确认任务是否快于首次轮询结束。
- 直接查看 `runs/<run_id>/stderr.log`。
- 当前实现会在终态补读日志并在重开页面时恢复；若仍为空，再判断 CLI 是否确实没有 stderr 输出。

### 结果摘要是空值

检查实时日志、`summary.csv` 和运行元数据。若日志已报“没有有效时间点”等错误，不应把仅创建了目录视为成功结果；优先修正日期、数据周期、触发器和股票池。

### 页面无法选择本机文件

- `127.0.0.1` 本机访问可用系统选择框。
- 局域网/远程访问不能控制服务器文件选择框，应上传项目或输入服务器路径。

### 端口无法启动

检查 `8766` 是否已被已有网页服务占用。优先复用已有服务；确需并行时显式指定其他端口，不要改用 `8765`。

## 修改后的验证清单

网页功能修改后至少完成：

1. `npm run build`，确认 TypeScript 和 Vite 构建通过。
2. 运行 Web、CLI 协议、项目导入、结果和状态管理相关自动测试。
3. 实际导入 `.kh` 并完成一次小范围 DuckDB 回测。
4. 核对状态最终为 `completed/100%`，结果目录和 HTML 报告存在。
5. 浏览器检查左右栏宽度稳定、日志自动位于底部、结果卡属于当前 `run_id`、控制台无错误。
6. 另做一次快速结束/失败/停止场景，确认日志与终态不会丢失。
7. 确认网页修改没有改变普通 `kh run` 和桌面端的结果。
